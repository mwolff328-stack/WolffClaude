You are running the nightly SurvivorPulse 50-Beta-User Acquisition reporting job. This is a REPORTING-ONLY job: you must NOT send any messages, contact any prospects, or take any outreach action. You only read existing Notion data and write summary rows.

**Notion tool:** use the OAuth Notion connector tools (`mcp__d77c6777-2678-446f-b1ea-d56a8303dfb6__notion-*` — `notion-query-data-sources` for reads, `notion-create-pages`/`notion-update-page` for the two writes below), not `mcp__notionApi__*`.

**Incident note (2026-08-18, do not remove):** the 2026-08-17 run of this job reported 0 signups and 0 all-time progress while 2 real signups (king_17, Ben/OrionTheTitan) sat in Beta Testers with Status=Redeemed. The job as originally written only ever queried Prospect Tracker and Outreach Log for signup counts — both were structurally blind to anyone who signed up through the beta-invite funnel rather than the Aug cold-outreach campaign. Beta Testers is the actual mechanism by which people become users (beta code / open-access redemption); it must be queried every run, not treated as optional context. Founder also confirmed several warm-DM prospects living only in Beta Testers (not Prospect Tracker) were backfilled into Prospect Tracker on 2026-08-18 — if new Beta Testers rows appear in future runs with no matching Prospect Tracker row, do NOT auto-create one (this job does not write to Prospect Tracker); just flag it in Blockers / Pivots Needed so a human can backfill it, the same way this incident was caught.

## Steps

1. Determine "today" as the current local date this job is running.

2. Query the full Outreach Log (paginate with start_cursor if has_more is true) and filter to entries with Outreach Date = today. Count them = Outreach Sent Today. Also compute per-platform breakdown (Reddit/Discord/X counts).

3. Query the full Prospect Tracker (paginate if needed). Filter to prospects with Date Contacted = today — these are today's outreach targets/prospects worked (used for Target 5 Prospects / Community Engagement Notes below). Do NOT trust any old/stale rows — always compute fresh from current data, and be aware some historical Prospect Tracker rows before 2026-08-13 may reference fabricated/unverified prospects per the tracker's "Sourcing Integrity Rule" note; ignore that historical caveat for date-filtered queries since you're only looking at today's real rows anyway.

4. Query the full Beta Testers data source (paginate if needed). Filter to rows with Date Redeemed = today — count = **Signups Today**. This is the authoritative signup count; see the incident note above for why Prospect Tracker / Outreach Log alone are not sufficient. Cross-check: also check Prospect Tracker for rows with Signup Date = today and Outreach Log for rows with Outcome = "Signup" and Outreach Date = today. If either disagrees with the Beta Testers count, use Beta Testers as authoritative and note the discrepancy in Win/Loss Notes.

5. Compute Response Rate This Week %: from the Outreach Log, take all rows with Outreach Date in the trailing 7 days (today minus 6 days through today, inclusive). Response Rate = (count of rows where Response Status is "Responded Positively" or "Responded Negatively") / (total count of rows in that window) * 100. If the window has zero outreach rows, report 0 and note "no outreach in trailing 7 days" rather than dividing by zero.

6. Compute Progress to 50: query the full Beta Testers data source and count ALL rows (any date) with Status = "Redeemed" (or, equivalently, Date Redeemed populated). This is the all-time running total toward the 50-user goal — it is authoritative. Cross-check independently via (a) Prospect Tracker rows with Status = "Signed Up" and (b) Outreach Log rows with Outcome = "Signup". If either cross-check disagrees with the Beta Testers count, use the Beta Testers count and note the discrepancy in Win/Loss Notes — do not silently average or split the difference.

7. Query the full Original Content Log (paginate if needed). Compute two things:
   - **Posted today:** rows with Date Posted = today. For each, capture Title, Channels, Pillar, and Description.
   - **Pipeline snapshot:** rows with Status in (Research, Draft, Ready for Review, Approved) — i.e. not yet Posted and not Archived — grouped by Status, with Title, Channels, and dwell time for each. Dwell time = today minus Last Edited (in whole days; report hours instead if under 24). Last Edited is Notion-managed and updates on ANY edit to the row, not specifically on a Status change, so treat the computed dwell time as an upper bound on "time in current status" and say so, not as an exact measurement. Sort each status group by dwell time descending (oldest/most-stale first) so the longest-stuck items surface at the top. Flag any Ready for Review or Approved item with dwell time over 48 hours as a likely blocker worth naming explicitly in Blockers / Pivots Needed, not just listing in Content Log Activity.
   Do not fabricate Verified Sources or Content text that isn't present — if a row has an empty field, say so.

8. Compute Day N: N = (today's date - 2026-08-07) in calendar days, plus 1 (so Aug 7 = Day 1, Aug 8 = Day 2, etc.).

9. Create a new row in the Daily Acquisition Brief database (data_source_id 811af450-479a-4e9c-869d-636f6ec438a8) with:
   - Day (title): "{Month} {Day}, {Year} - Day {N} Acquisition" e.g. "Aug 17, 2026 - Day 11 Acquisition"
   - Brief Date: today's date
   - Signups Today: the count from step 4
   - Progress to 50: the count from step 6
   - Outreach Sent Today: the count from step 2
   - Response Rate This Week %: the value from step 5
   - Target 5 Prospects: list the names/handles of prospects with Date Contacted = today from step 3 (if fewer or more than 5, list what actually happened — do not pad or truncate to force exactly 5). If none, write "No prospects contacted today per Prospect Tracker."
   - Community Engagement Notes: summarize any Notes/Contact Info field content from today's touched prospects (step 3) that describes community engagement (Reddit thread replies, Discord activity, etc.). If nothing notable is logged, write plainly "No community engagement activity logged today" — do not invent content.
   - Win/Loss Notes: summarize any notable responses today (positive/negative) from the Outreach Log Response Text/Response Status fields for rows with Outreach Date = today or Response Received = today, PLUS any signups from step 4 (name each signup and which tracker recorded them). If nothing notable, write "No notable wins or losses logged today."
   - Blockers / Pivots Needed: check Notes/Contact Info fields on today's touched prospects and today's Outreach Log Next Step fields for any blocker language. Also flag (per the incident note above) any Beta Testers row with Date Redeemed = today that has no matching Prospect Tracker row. If none found, write "No blockers logged today."
   - Content Log Activity: report both parts of step 7. First, what was Posted today (Title, Channels, Pillar for each; "No content posted today" if none). Second, the pipeline snapshot by Status, listing titles under each non-empty status ("Content pipeline is empty" only if Research/Draft/Ready for Review/Approved are all empty). Flag items that have sat in Ready for Review or Approved without being posted, since those are the stages most likely to represent a blocker rather than routine work-in-progress.

10. Update the Progress Tracker dashboard (data_source_id 78368978-fb49-41e1-9a7e-2f6312fc0136) so it stays current:
   - Find the existing "Overall Signups Toward 50-User Goal" row (Channel = Overall) and update: Current Count = the all-time Redeemed count from step 6, % Progress = Current Count / 50 * 100, Notes = brief note with today's date and what changed.
   - **Conversion Rate % — use a cross-system denominator, not Outreach-Log-only.** Dividing signups by Outreach Log row count alone returns 0% even when real signups exist, because Beta Testers signups (the beta-invite funnel) are not logged as Outreach Log rows — this was exactly the 2026-08-17 bug. Instead: build the set of unique people contacted = (distinct Outreach Log "Prospect Name" values) UNION (distinct Beta Testers "Handle" values), deduplicated by normalized identifier. Normalize each identifier before comparing: strip leading "u/" or "@", strip any parenthetical suffix (e.g. "(reply 2026-08-16)", "(Follow-up)"), trim whitespace, lowercase. Two identifiers are the same person if their normalized forms are equal, or if one normalized form is a substring of the other. Conversion Rate % = (Redeemed count from step 6) / (size of that deduplicated unique-contacts set) * 100. State the arithmetic in the Notes field (row counts, dedup count, overlap found) so it's auditable on the next run, not just the final percentage.
   - Find the existing "Reddit Channel Progress" and "X (Twitter) Channel Progress" rows and update Current Count (all-time Redeemed count for that platform, using Beta Testers "Source" field for Beta Testers rows and Prospect Tracker/Outreach Log "Platform" field for cold-campaign rows — e.g. Beta Testers Source values "Reddit DM" and "Reddit Post" both count as Reddit) and Conversion Rate % (same cross-system dedup method as above, scoped to that platform) similarly. Leave Target/% Progress as-is unless a per-channel target has since been explicitly defined elsewhere (do not invent one).
   - If Discord or Organic now show any activity (any Prospect Tracker row with that Platform, any Outreach Log row with that Platform, or any Beta Testers row whose Source indicates that channel) that didn't exist before, create a new row for that channel following the same pattern as Reddit/X (Current Count = all-time Redeemed count for that channel, Target = 0 unless a real target is defined, Conversion Rate % computed the same way, Notes explaining the numbers and that no per-channel target is defined in the playbook). Use API-query-data-source to check first rather than assuming Discord/Organic rows already exist.
   - Use API-patch-page to update existing rows (query the data source first to get their page IDs by matching Metric title / Channel select value) rather than creating duplicates.

11. Do not send any messages, DMs, replies, or outreach of any kind. Do not modify Prospect Tracker, Outreach Log, Beta Testers, or Original Content Log rows — this job is read-only against all four; it only writes to the Daily Acquisition Brief and Progress Tracker. Do not fabricate any prospect, quote, content title, or event that isn't actually present in the Notion data — if a field has nothing to report, say so plainly.

12. Report back a short summary: Day N, outreach sent today, signups today (and which tracker(s) recorded them), response rate this week, all-time progress to 50, content posted today (count + titles, or "none"), any content sitting in Ready for Review/Approved worth flagging, and confirmation both the Daily Acquisition Brief row and Progress Tracker updates succeeded.
