**TWO CORRECTIONS to this file's earlier content, both verified live on Dev 2026-08-20:**

1. **"Buyback toggle is a NO-OP" is FALSE.** The client path is wired end to end (SeasonReplayView state → all 4 `assignIndependentPicks` call sites → optimizer path → UI toggle) and revival logic exists at `assignIndependentPicks.ts:881`. Proof from the repo's own `verification.test.ts`, same season/strategies/entries with the flag as the only difference: 2023 Pure Win Prob **13 → 22** entry-weeks, 70/30 Blend **17 → 23**. What IS wrong: **revivals are FREE** (no fee/cost handling anywhere in the sim, though Pool Setup collects a fee and schema stores `buybackFee`) — the honesty-relevant defect, since free extra lives inflate survival most for aggressive strategies, contradicting SST-783's "buyback does not reward aggression". Also `runSeasonOptimizer` (backtesterSweepService.ts:673) underscores/drops the params, and **no test compares ON vs OFF** (numbers sit in separate describe blocks).

2. **The 2025 breakage is not a deleted row, it's missing provenance for ALL FIVE seasons.** `04e2471b-…` (the hardcoded 2025 pool in `POOL_BY_SEASON` + `DEFAULT_POOL_ID`) 404s on Dev; its only creator is `scripts/seed-e2e.ts`, which `explainNonE2eSeedableHost` hard-blocks from helium and the shared dev DB. The 2021-2024 "CMEA Prototype Demo Pool" ids (`a1b2c3d4-*`) have **zero hits repo-wide** — nothing creates them; they exist because someone inserted them once. No committed 2025 fixture either (`client/src/backtester/data/` is 2021-2024 only; pinned by SST-157 `hasFixture(2025)===false`). Re-seeding one pool papers over it.

**Why it stayed broken — three stacked layers of silence** (the reusable pattern here): `fetchSeasonDynamics` swallows errors → `[]`; `assignIndependentPicks` applies `pickShare ?? 50`, turning empty into plausible constant data; and `e2e/backtester.spec.ts:399` — the ONLY automated check on that pool — **explicitly accepts 404 as a pass** (`expect(status).not.toBe(0)`, comment "A 404 is expected"). Fail-open tripwire. Symptom: on 2025 every strategy returns an identical 20.0% Deep Run Rate and Pick Share renders "—" for all 32 teams, while 2021 separates normally. Since anti-chalk tilt is the only axis that moves outcomes, a constant-pick-share season yields a meaningless back test that still looks like a result.

**Root fix chosen:** pick popularity is LEAGUE data, not pool data. `server/services/seasonGridRankService.ts` already established the pool-independent pattern (its header explains a uniform pickShare "would silently defeat the whole point"). Re-point the Back Tester the same way and `POOL_BY_SEASON`/`DEFAULT_POOL_ID` die with the whole class of problem.

**Deferred to the UI overhaul, still real honesty defects — do NOT let these reach non-admins first:** the Expected Return (winner-take-all) tile (`OptimizationResults.tsx:532` = `deepRunRate * poolSize / entryCount`, a survival proxy rendered as a money multiple — the exact conflation the founder's own Reddit post debunks) and the hardcoded `- 62` chalk baseline in Edge vs Chalk. Also still true: every Back Tester output is a survival metric (Deep Run Rate, Weighted Survival Score, Survival Timeline, Upset Avoidance) — no winning metric, no wipeout metric. Adding those is the story AFTER the UX is defined.
