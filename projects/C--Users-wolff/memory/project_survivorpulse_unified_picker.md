`client/src/components/PickGrid.tsx` → `TeamPickerModal` is THE pick-editing surface for Pool Details, Make Picks, AND Game Plan. `RankedTeamDrawer` was deleted (SST-762). One modal, two tabs: Ranked (default, non-persistent) + By Division. Testids: `ranked-team-toggle-<teamId>`, `team-picker-option-<teamId>` (By Division), `team-picker-clear`, `team-picker-tab-division`.

**Stories:** SST-762 Done (unification). **SST-858 Ready** (display rework: drop Composite + flexibility labels, "Pick %"→"Field Exposure", 6-col header-row layout @600px, matchup, header-padding fix, responsive 2-line mobile card, PICK_LOCKED handling). **SST-859 Ready** (By Division parity — that tab was a static roster with only `id`/`city`, sharing NOTHING with Ranked; rewire to the same `rankedTeamsRaw` result, client-side join on teamId, carry the SAME overall rank not a division-local re-rank).

**Composite Score (dropped from display 2026-07-15, internal ranking only):** `compositeScore100 = 0.80·coreScore100 + 0.20·poolDynamicsScore100` (falls back to core if pool-dynamics null); `coreScore100 = 0.70·weeklyScore + 0.30·futureUtility`. **Confirmed SEPARATE lineage from strategy scoring** (`shared/strategyEngine/pickScoring.ts::scoreTeamForStrategy`) — no shared code, two engines both emitting a ranking number, never comparable across surfaces. Gotcha: **the displayed `compositeScore100` was never the sort key** — the sort uses `enhancedCompositeScore ?? coreCompositeScore ?? expectedValue` (optimizerService.ts:1911-1919). Dropping it also retired a standing SST-785 governance violation (no Composite/EV/$ on trust surfaces); Game Plan DOM-scans for these strings.

**"Saves well"/"Neutral"/"Spend now" DROPPED entirely (Stan + Curie independent rulings, founder-confirmed 2026-07-15).** Curie's claim boundary: **"none — there is no copy to write"**; explicitly pre-empted an honest restatement like "top third this week". Mechanism was `flexibilityTier` = within-week percentile of `futureUtility` (optimizerService.ts:1891-1903). Why dropped: percentile is scale-free (fires identically on noise and signal); a mass tie labels EVERY team "Spend now"; a single candidate → "Saves well"; cohort denominator includes unavailable teams; **semantically inverted** — futureUtility is weighted POSITIVELY (+30% of core), so "Saves well" displays on the team the engine steers you to SPEND; and it doesn't survive the SST-779..783 portfolio reframe (its scarcity term counts other TEAMS in the schedule, not correlation among ENTRIES). Any future forward-looking signal must be rebuilt from portfolio-thesis primitives, not relabeled from this.

**futureUtility is NOT inert (Stan quantified 2026-07-15):** 32/32 healthy in every well-formed week incl. wk16; zeroing it moves 8-11 of 32 positions/week — but it almost never changes the **#1 pick** (current-week strength dominates the top slot). NaN only hits teams an entry already used. **The RANKING is NaN-safe** (explicit `isNaN` guards in `compositeScoreWithLeverage` + `safeNum`); only the label path was NaN-unsafe (`??` doesn't catch NaN → percentile 0 → "Spend now"), which is moot now the label is gone. A committed capture (`GET_optimizer_recommendations_week5.json`, 34/34 futureUtility=0) is unreproducible today and came from helium — treat as stale, NOT a live defect.

## Game Plan coupling (critical — don't break these)
- **`shared/teamColors.ts` is canonical and ALREADY EXISTS on 2026-v1** (Game Plan built + promoted it 2026-07-15). `TEAM_COLORS: Record<teamId,{primary,textOnPrimary,secondary?}>` + `getTeamColors()` + `teamPrimaryColor()`. All 32 teams, textOnPrimary white (several primaries deliberately darkened from official brand hex for contrast). **Import it; never build a second palette; refine IN THAT FILE, never at a call site.**
- **`PickGrid.tsx` exports `TeamPickerModal`, `SelectedCell`, `Team` as NAMED EXPORTS** (added `502ac96b`) — Game Plan's Season View + Week View import them. **Do not break or rename.** Also never rename existing testids/props/pick-save mutation shape.
- **Kickoff lock:** pick writes return `409 {errorCode:'PICK_LOCKED', lockedTeamIds}` when a CHANGED team's game already kicked off (unchanged resubmits never lock). The client currently does `throw new Error(body.message)` which DISCARDS errorCode/lockedTeamIds — SST-858 fixes this, improving both surfaces since Game Plan reuses the modal + mutation.
- **Auto-vs-confirmed has a durable source of truth:** `pick_confirmations` table. **Pick exists + no confirmation row = auto/unconfirmed.** Manual edit via TeamPickerModal auto-confirms server-side.
- **⚠️ RESET-TO-AUTO GOTCHA (story not yet created):** auto-applied picks from `POST /api/me/gameplan/apply` write via `storage.replaceEntryPeriodPicks` **directly, NOT the PUT route** — that is what keeps them UNCONFIRMED. If Reset-to-Auto re-applies per-entry, it **must use the same path or it will accidentally auto-confirm** the pick. The apply path is per-entry capable and skips confirmed unless `overwriteConfirmed:true`. Auto-allocation is regular-season only.
