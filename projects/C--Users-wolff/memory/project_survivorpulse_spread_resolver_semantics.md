Hard-won facts about `server/services/odds/spreadResolver.ts` and the fabricated-data detector, from SST-866 triage (2026-07-16). All verified against real repo data, not assumed.

**STATUS: both guards SHIPPED 2026-07-16 (founder greenlit same day).** SST-866 → `942eeb54`: `CLOSING_TIER_TOLERANCE_WINDOW_MS` (7 days, exported) in spreadResolver — implausible closing/post-kickoff canonical claims return null from `canonicalFieldsPopulated` and fall through the cascade (never throw); CA1 golden byte-identical (goldens hardcode weeks 1-18, playoff rows structurally out of scope); real 2025 max pre-kickoff gap measured 29.25h (`2025-20-CHI-LAR`), all 280 closing rows pass the window. SST-868 → `d28fb9e1`: `hasCompleteForwardData` now also flags fabricated when modal |spread| share ≥50% (`FABRICATION_SHARE_THRESHOLD`) on weeks with ≥8 games (`MIN_GAMES_FOR_SHARE_CHECK` — small-n binomial guard; the old exact-identity check keeps its n≥3 gate). Either guard catches the W12/16 incident independently. W12/16 seed data itself cleared by founder SQL (all tiers nulled, game rows kept). Facts below remain the WHY.

**1. `closing_at_kickoff` lines are captured BEFORE kickoff, not at/after it.** The intuitive invariant "a closing line cannot predate its own kickoff" is WRONG and was filed as a fix proposal before Felix disproved it. Real closing captures in `data/season-exports/games_2025.json` land ~5 minutes to ~29 hours PRE-kickoff (12 real completed 2025 playoff games, wks 19-21, e.g. `2025-19-CAR-LAR`). A `spread_used_at >= game_time` rule breaks a currently-green test (`tests/spreadResolver.test.ts:35-50`) and degrades real historical rows. Worse, it's a BACKWARDS signal: 268/280 regular-season `closing_at_kickoff` rows only pass a strict `<` check because `spread_used_at` coincidentally EQUALS `game_time` — a fallback artifact when `lockedSpreadAt` was never recorded. So the naive rule penalizes accurately-timestamped rows and rewards fallback-defaulted ones. Any plausibility guard must be a **tolerance WINDOW** (days-out threshold; fabricated data was ~4-5 months out vs. real minutes-to-hours), and must **fall through, never throw** — fall-through recomputes identically from the same `locked_spread`/`locked_spread_at` columns (idempotent, zero risk), throw turns green historical resolutions into hard failures.

**2. The resolver is a FALLBACK CASCADE — clearing canonical fields alone is not enough.** Order: canonical (`spread_used_for_analysis_home` + `spread_used_at` + `spread_finality_tier` + `spread_source`, all four required to short-circuit) → `override_current_spread_home` → `locked_spread` → `pre_kickoff_baseline_spread` → `imported_home_spread` → `game_odds_snapshots` (via `optionalSnapshots`, threaded in by the SST-862 fix). Nulling only the canonical 4 on a row sourced from `imported_snapshot` lets it drop straight back to `imported_home_spread` and re-derive the same value. To truly clear a spread you must null every tier together. Cleanup SQL template: scratchpad `cleanup-2026-w12-w16-seed-spreads.sql`.

**3. Stan's empirical envelope — real NFL weeks vs. fabricated ones (90 real weeks, 5 seasons, 1,359 games from `client/src/backtester/data/nfl_games_{2021..2024}.json` + `data/season-exports/games_2025.json`).** Real weeks: max share on a single `|spread|` magnitude NEVER exceeded **37.5%**; distinct magnitude count NEVER below **8**. Cross-validated against a different vendor (`data/2026/4for4_lookahead_lines/4for4-week1.csv` → 8 distinct, matching the floor exactly). The known-fabricated dev rows: 2026 W12 = 81.3% share / 3 distinct; W16 = 93.8% / 2 distinct. Disjoint by ~2x on both metrics. Stan recommends (medium-high confidence) flagging a week fabricated when `distinctMagnitudes.size === 1` **OR** modal magnitude share ≥ **50%** — 12.5pts of margin against every real week, 31pts against both fakes. Would change his mind: any verified real week above ~45% share. NOTE: this is a **product-rule change to a governed invariant** (founder's 2026-06-30 rule is "if EVERY game has the same spread"), needs founder + Curie sign-off, NOT an implementation detail. Real NFL weeks cluster far less than intuition suggests — beware inventing a threshold; -3/-2.5/-3.5 dominance does NOT produce high single-magnitude concentration.

**4. The fabrication detector (`ForwardAdapter.ts:214-221`) is defeated by trivial variance.** Fires only when distinct `|spread|` count is exactly 1. 13-of-16 identical sails through. Its fixtures (`tests/strategyEngine/ek6.forwardDataCompleteness.test.ts`) only ever test the two extremes (all-identical TC-EK6-U17/U19a, mostly-diverse TC-EK6-U18) — never majority-share-with-noise, which is the shape real seed data takes.

**5. Fixture-blindness is a confirmed structural class, not bad luck.** SST-861/862/863/866 all: green unit suite, caught only by live data. Vlad's diagnosis — fixture builders are hand-authored by whoever just wrote the rule, built to their clean mental model of it, so they prove the code matches the spec but cannot catch the spec failing against real data entropy. Countermeasure: build fixtures from ACTUAL observed distributions, and test the failure mode the rule exists to prevent, not the rule as written.
