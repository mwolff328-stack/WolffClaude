Founder decision 2026-07-20: REMOVE the entire "pick confirmation" concept from Game Plan/cockpit. Rationale: SurvivorPulse is NOT the system of record for picks, so a separate confirm step is superfluous and complicates UX. New model: a made pick (auto-allocated OR manual) IS confirmed by definition, and persists until the user changes it manually or re-runs the auto-allocator.

Impact eval (3 parallel code sweeps) confirmed confirmation is a self-contained UI/workflow state: NOTHING analytical reads it (derivedMetrics, poolDynamicsService, optimizer, EV/field-size, portfolio lens, pick-popularity, backtesting, scoring all clean). Removing it breaks no math. Surface: one table `pick_confirmations` (shared/schema.ts ~601, migration 0022, non-cascading FK), the `confirmedWeeks` cockpit DTO field, POST .../picks/:periodKey/confirm route + cascade, confirm/clear calls in PUT/batch/both reset-to-auto, the apply overwriteConfirmed+skipped-confirmed logic, SST-864 invariant + tripwires + PRODUCT_INTEGRITY_RULES Rule 4 + KNOWN_WRITE_SITES registry, and ~15 client files (StandingStrip, SeasonGridSection, WeekViewSection, standingMath, ApplyBar, PickGrid, 3 confirm hooks).

Key surprise: projected weeks (2026 Wk 2-5) are NOT symmetric. Auto-fill never persists them (skipped-projected), but a manual tap DOES save a real confirmed pick today (no odds-basis gate on the write path).

3 LOCKED founder decisions (binding on grooming):
1. Re-run OVERWRITES all existing picks, WITH a heads-up ("replaces existing picks in N pools" in the apply modal). Remove the "Replace confirmed picks too" checkbox + skipped-confirmed outcome.
2. Projected weeks LEAVE AS-IS: no new gate, auto skips / manual persists as today.
3. Standing readout STRIP IT DOWN: drop the "N/M confirmed through Week W" fraction, keep only "X alive"; minimal picked/no-pick chips. Lets computeConfirmedThroughWeek + SST-890 playoff domain-anchoring be deleted outright, not reframed.

Stories (under epic SE-91 Game Plan): SST-935 redefine standing from pick-presence (keystone) -> SST-936 remove confirm UI + strip readout -> SST-937 remove confirm endpoint/writes/invariant (backend) -> SST-938 simplify Apply (overwrite+heads-up) -> SST-939 reconcile Reset-to-Auto + Auto-allocated pill (PickGrid) -> SST-940 drop pick_confirmations table (phase 2, dev-first, founder-run helium+prod row count first). 936 & 939 both touch PickGrid.tsx (sequence deliberately).
