2026-09-08: Replit Dev server failed to boot with `Error [ERR_MODULE_NOT_FOUND]: Cannot find package 'markdown-it-ins' imported from server/email/renderBroadcast.ts`. `markdown-it-ins` was already correctly declared in `package.json` (added alongside the founder-broadcast-emails feature, commit range ending e61b264b) — the package just wasn't actually installed in Replit's `node_modules`. The same gap independently reproduced in an unrelated worktree until `npm install` was run there too.

**Why:** each environment (a git worktree, the Replit container, a CI runner) has its own independent `node_modules` install state. Adding a dependency to `package.json` in one session/worktree does not propagate it anywhere else — every environment needs its own `npm install` to pick up a new or changed dependency.

**How to apply:** when `ERR_MODULE_NOT_FOUND` (or an equivalent "cannot find module") fires for a package that's genuinely listed in `package.json`, don't chase the import path or the dependency declaration first — check whether it's actually present under that environment's `node_modules`, and if not, just run `npm install` there. This is a per-environment install-state gap, not a repo bug, so it needs no code change or commit — only the confirmation that `npm install` was run in the environment that's actually failing (worktree vs. Replit vs. CI are NOT interchangeable here).
