**Facts (2026-09-13 to 2026-09-25, SST-1583):**
- `notion-update-page` `update_properties` REPLACES the whole property value; an agent that "patched" Test Cases in 4 partial calls left a 15K-char fragment of a 200K-char property. A 2026-09-22 human-readable (🗣️) backfill then did the same again. Nothing in the tool warns you.
- The public REST API rejects a rich_text write with more than **100 items** or any item over **2000 chars** (400), so one atomic REST write holds at most 200,000 chars. The hosted MCP tool wrote properties with 499 segments and single segments over 18K chars, but only by the model emitting the full text in one call, which is why agents fell into partial writes.
- REST cannot carry Notion formatting on a big property: AC had 239 inline-code spans, so a REST rewrite turns them into literal `backticks`. Description and AC are plain text otherwise (only accidental auto-links on names like `testing.md`).
- The AC/TC text is agent-facing; the 🗣️ lines are the human layer (Operating Model, 2026-09-22).
- Local backups in Temp get cleaned (~10 days); the durable copy that saved the day was the earlier session's saved tool-results under `~/.claude/projects/<worktree>/<session>/tool-results/` (full-page reads), plus the corrupting agent's own PowerShell edit scripts inside `auto-mode-classifier-error.txt`, which let the lost r11 edits be re-applied exactly (length matched to the char).

**Safe procedure (worked, 6 writes, all byte-verified):** never let agents write Notion properties. Agents edit LOCAL files with the Edit tool (surgical old->new); the orchestrator validates (ids present/ordered, a 🗣️ line above every entry, size <= 199,000, no dropped AC refs/file names) and does ONE atomic REST PATCH per property from a script that (1) aborts unless the live text still equals the frozen baseline, (2) checks <=100 items and no split surrogate pair (emoji), (3) reads the property back and compares byte-for-byte. Dry-run first. Copy backups to `~/.claude/backups/<ticket>/`, not Temp.

**Update 2026-09-28 (SST-1583, rounds r17-r23, ~8 guarded writes, all byte-verified):** the loop that scaled: reviewers (Felix especially) return machine-checkable `OLD:`/`NEW:` line pairs (each OLD occurs exactly once); a small orchestrator script (`apply-pairs.mjs`) applies them to the LOCAL work files and aborts before writing if any OLD fails to match once; agents then sweep and fix wording; only then the guarded write. Size relief without deleting anything: MOVE non-test blocks (AC revision history, TC notes, the AC-to-TC Traceability table) to the END of the Description property (139K free) and leave a pointer; Description opens with the 🗣️ line, so append, never prepend. TC still hits the 100-item x 2000 ceiling every round: budget the cuts before adding (stale line ranges, rationale phrases, over-long 🗣️ glosses). The genuine Cass (Codex) found a real, code-derived gap EVERY round (test fixtures that could not fail, error-precedence collisions, a mismatch between server response and client handling), converging from 6 MAJOR to 1 over four rounds, so fix rounds must go back to Cass, not just the persona reviewers. Cass quota can run out mid-loop (2026-09-28, ~4h): run a clearly-labelled fable substitute and keep the genuine pass owed. See [[bash-tool-quote-parse-failures-use-script-files]] for the codex-companion `--prompt-file` invocation.

**Update 2026-10-02 (SST-1797): page BODY edits can use the same guarded pattern over REST.** `GET /v1/pages/{id}/markdown` and `PATCH /v1/pages/{id}/markdown` (body `{type: "update_content", update_content: {content_updates: [{old_str, new_str}]}}`) work with header `Notion-Version: 2026-03-11` and the normal `NOTION_TOKEN` (the 2022-06-28 version used for properties does not have them). A script builds each (old, new) from the agents' local section files (match the exact heading line, replace to the next heading), asserts every `old_str` occurs exactly once on the CURRENT text, saves a backup, PATCHes once, then re-GETs and compares. The read-back is never byte-identical: Notion collapses blank lines and escapes `~ { } < >` with a backslash, so compare after stripping blank-line runs and `\\(punct)`. This keeps ~30K chars of replacement text out of the model's context and avoids hand-pasting `content_updates`. Targeted edits keep anchored comment threads on untouched blocks; do not use `replace_content`. Genuine Cass found 2 MAJOR real-code contradictions in a spec three personas and an orchestrator had already approved (a fixture the real service cannot produce; a recovery step that contradicts the shipped `useAuth` rule), so a redesign always goes back to Cass even after the approvers sign.

**Why it matters:** a spec at 195K+ of a 200K ceiling (SST-1583's Test Cases) cannot take new TCs without cuts; budget space before adding, strip revision-history provenance (it belongs in comments), and put build-time findings in comments.

**How to apply:** any grooming round on an XL ticket, any agent brief that mentions writing Notion properties, any "restore/fix Test Cases" task. See [[project_survivorpulse_notion_page_read_truncates_rich_text]] and [[feedback_survivorpulse_hardcoded_notion_page_id_typo_posts_to_wrong_ticket]].
